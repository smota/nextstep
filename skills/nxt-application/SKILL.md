# Nextstep application

Use the external agent to research, reason, draft, render, and collaborate. Use the `nextstep` CLI for bounded context and every durable career-record mutation.

A direct request to prepare or revise an application package authorizes the in-scope private files, renditions, QA, and package registration needed to complete it. Do not ask for redundant approval. Submission, outreach, destructive actions, sensitive artifact adoption, and publication retain their own confirmation boundary.

Before guiding or refining an applicant's work, read [adaptive guidance](../references/guidance.md) for optional questions, scope, and review.

## Work from the current contract

- Read [context](../references/context.md) before broad evidence retrieval.
- Read [application attempts](../references/application-attempts.md) for package registration, submission, reconciliation, and closure.
- Read [artifacts](../references/artifacts.md) for status, contract checks, adoption, registration, and QA.
- Read [entities](../references/entities.md) only when the package needs missing Company, Opportunity, or ApplicationAttempt records.
- Read [interactions](../references/interactions.md) for confirmed events and their required evidence.
- Read [workflow support](../references/workflow-support.md) for readiness and submission views.
- Read [validation](../references/validation.md) before reporting completion.

Use `nextstep command describe --command "<name>" --json` rather than guessing an option or payload. Mutations use the versioned envelope and the current expected revision when required. Never edit registered JSON, indexes, audit logs, transaction state, or snapshots directly.

Preserve direct user edits as user revisions. Never overwrite them or reverse-map a rendition into canonical content. Treat structural QA, visual QA, and transmission evidence as distinct.

Record a submission or outcome only from confirmed facts. Preserve date-only precision. Keep transmitted artifact selection as `unknown`, `confirmed_none`, or `confirmed` with exact IDs; never infer attachments, channel, recipient, date, stage, or outcome. A later working-file revision must not change an immutable transmitted snapshot.

Opportunity analysis without a requested ApplicationAttempt remains read-only. A draft is not proof of submission. A conversation or contact does not force an ApplicationAttempt. Apply a Strategy or Experiment only when it was explicitly selected or is already active and relevant.
